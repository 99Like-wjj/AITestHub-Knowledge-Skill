# 项目知识 Skill 架构与依赖约束

规范版本：2026-11-14.1。

## ARCH01 职责与结构

- src 保存本仓库的类型、领域规则和确定性 helper；不以 helper 代替当前 AI 的理解和业务判断。
- skills/ath-project-knowledge 保存入口及实际引用的规则和经验，人工友好展示仍由平台承接，不另建并行用例或报告产品。
- 业务内容、平台授权、Tool/Result/Workspace/FileChannel 端口与私有落盘边界分别表达。仅使用本仓库已声明且实际需要的端口，不为统一形式另造鉴权、HTTP SDK 或网络重试。
- scripts 保存明确构建、打包、契约导入及完整性检查入口；测试专用代码和真实联通记录留本地，不进入正常源码或分发包。
- contracts 或 src 内的契约快照按当前包布局固定来源与摘要；复制、生成、校验不表示业务已批准或真实宿主已兼容。

## ARCH02 禁止的依赖与副作用

- 不运行时跨仓库 import 平台、其他 Skill 或开发机绝对路径；必要集成使用固定契约和可信注入端口。
- 不在库导入时读取用户秘密、初始化真实平台连接、创建目录或发起写操作；需要同时复用的 CLI 将执行动作放在入口保护之后；纯构建或打包脚本明确为仅直接执行，不被运行库导入。
- 领域规则与平台 adapter 分离，AI 只提出业务意图；角色、对象归属、修订与实际回执由平台继续校验。
- 稳定 ID、CAS、原请求及未知事实不能为恢复而更换、清空或按名称猜测。
- 新增依赖、共享层或例外需说明职责和兼容影响；不为层次指标制造无意义封装。

## ARCH03 构建与分发

- 以本仓库 package.json、tsconfig.json 和 scripts 中实际构建器为准，生成输出不手工维护。
- 不依赖被忽略的测试、证据、旧 dist 或其他仓库来完成正常源码构建。
- 包 files、完整性清单与引用文档须闭合；保持旧冻结发行物原字节，生成新包不冒充旧包验证。
- 构建、解包、工具信息、宿主安装、自动加载、MCP 和真实业务分别给证据；本仓库没有全库架构自动门禁，新增 import 与依赖需逐项审查。

## ARCH04 本仓库业务边界

- 轻索引和正文按需读取；首次双边比较后由人选择，缺席不删，提交再验基准。
- 配置以平台结构化服务为权威，知识仅保存非秘密说明和引用；代码现状不自动成为正确业务规则。
- 工作稿及原比较回执在私有工作区，未知先查原账，不换 key 或自动合并。
