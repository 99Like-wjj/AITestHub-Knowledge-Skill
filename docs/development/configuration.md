# 配置与秘密约束

规范版本：2026-11-14.1。新增或修改可配置能力前，先按下表归类，再决定存放位置。

## CFG01 四类信息

| 类型             | 示例                                                                          | 存放规则                                                                                  |
| ---------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 业务和协议不变量 | 状态枚举、协议版本、Schema、已应用迁移摘要、安全拒绝规则                      | 留在相应契约或版本化代码，不为“可配置”随意开放修改                                        |
| 可移植默认值     | 本地监听方式、通用产品目录名、确有依据的开发默认参数                          | 集中定义并注明用途；不能伪装成用户真实部署                                                |
| 实例和环境绑定   | 实际 host、origin、平台或账号 UUID、SSH 绑定、真实绝对目录、模型或对象实例 ID | 外部配置或可信宿主注入；代码只声明字段、模板与校验，不藏在脚本、Dockerfile、注释或 README |
| 秘密             | 密码、Key、Token、Cookie、私钥、带凭据连接串                                  | 独立受限文件或既有 broker；仅传安全引用，不写普通元数据配置                               |

不是所有 UUID、IP、URL、hash 都是实例信息。冻结契约 ID、迁移 checksum、文档保留地址、安全网段和公开协议常量有合法用途；审查须说明类别，不能一刀切替换，也不能用“只是常量”掩盖真实部署绑定。

## CFG02 统一入口与显式依赖

- 一个值有一个权威来源，不在多个 controller、worker、脚本和前端常量中各维护一份。
- 优先复用现有配置读取器、Schema 和依赖注入。领域规则不随处读取 process.env，不把配置读取散落到业务分支。
- 在使用该能力的入口加载并校验配置；导入通用模块不得连数据库、发模型、读秘密或执行部署。
- 只校验当前入口必需的配置。没有云配置不应阻塞无关的本地纯函数能力；需要真实目标的入口则必须明确失败，不能回落到某个真实默认实例。
- 凭据路径本身属于实例元数据；凭据值与路径分别保护。前端仅能获得公开配置，VITE_ 不能携秘密或后端受限内容。

## CFG03 校验与失败

- 边界输入先作结构校验，限制类型、枚举、范围、必需项、未知字段和相互依赖；不能用类型断言替代。
- URL、目录、host、文件名等按用途单独验证；拼接不能越过允许根目录或改变目标来源。
- 对已受控的运维配置继续验证真实路径、链接、大小和已审核摘要；复用现有读取器，不写第二套宽松解析。
- 不安全、缺失或变化的配置给出安全错误码和变量名，不输出值或完整敏感路径。
- 缺配置、服务不可用、资料不被许可和真实联通失败分开表达。配置保存不等于真实能力已验证。

## CFG04 模板与覆盖

- 模板使用明显虚构的 example.invalid、占位符或说明，不从真实文件复制后局部遮盖。
- 模板只保字段结构和非秘密说明。不得填真实账号、平台身份、SSH 指纹、对象 ID 或私钥。
- 当前配置的来源及覆盖顺序必须写明；没有明确需求不新增另一套 .env、数据库或宿主配置权威。
- 运行配置、开发配置、实例配置、包元数据、生成 Schema 和测试夹具分别管理。专用测试材料不得借“示例”名义混入分发包。
- 已发布冻结文件保持原字节；修改模板或 Schema 时更新明确版本和验证，不改历史 hash 让旧包看似兼容。

## CFG05 安全配置不授执行权

配置外置后，原目标身份、版本、授权、精确备份、签名、排空、目录与主机 Key 等保护必须保留。不得将“读取配置成功”当作迁移、部署、换 Key、重建锚点或业务重放的授权。

秘密不进入日志、报错、截图、报告、MCP 参数或输出、模型上下文、前端初始状态和构建产物。错误或调试代码也受同一约束；禁止先泄漏后靠展示层掩码补救。
